## 3. What reading the installed extractor sources established

These are facts read from `gallery_dl 1.32.21` / `yt_dlp 2026.11.23` in the project virtualenv.
They shaped the adapters; they are **source-reading evidence, not live evidence**.

### gallery-dl `-j` output format (verified by running the real tool against a loopback server)

A JSON array of messages: `[2, {directory metadata}]`, `[3, "<url>", {file metadata}]`,
`[6, "<url>", {...}]` (queue) and, when the extractor raised, `[-1, {"error": "<Class>", "message": "..."}]`.
Keys starting with `_` are filtered out. Exit codes are a bitmask (unsupported URL = 64).
The `directlink` extractor has **no `num`**, so `{num}` renders as `None`: file-to-item mapping must
never trust a missing `num`.

### TikTok (T01.2)

* `tiktok:post` matches both `/video/<id>` and `/photo/<id>`. yt-dlp's `TikTok` extractor does
  **not** match `/photo/<id>` (pattern check) - photo mode can only come from gallery-dl.
* For a photo post gallery-dl yields one `Url` message per image with a 1-based `num`, width/height
  and `type: image`, **followed by an audio `Url` message** unless `-o audio=false` is set.
  The adapter must disable audio/covers/subtitles and must reject any non-image item (task: "do not
  return an audio track or fabricate a video").
* Extraction failures inside `TiktokExtractor.items` are **logged, not raised** (`Failed to extract
  post`), so a failed post can produce an empty dump with exit status 0. Zero items is therefore an
  error, not an empty success.
* Short links (`vm.`, `vt.`, `/t/`) become `Queue` messages (a second extractor). The project
  resolves short links itself, with redirect and address validation, before any extractor runs.

### Instagram (T01.3 - T01.5)

* `instagram:post` handles `/p/`, `/reel(s)/`, `/tv/`, optional `/<user>/` prefix and `/share/...`.
* Per-file metadata: `num` (1-based), `media_id`, `shortcode`, `width`, `height`, `video_url`
  (None for photos), and optionally `audience`, `subscription`, `expires`.
* **A carousel item without image data is skipped with only a warning** (`Missing media in post`),
  and `count` is computed *after* the skip. `count` therefore cannot prove completeness; the
  adapter scans for that warning and marks the result `partial` / never `complete` without it.
* `instagram:stories` with `/stories/<user>/<id>` fetches the user's whole reel through the API but
  yields **only** the item whose `pk` equals `<id>`; if absent it raises `NotFoundError("story")`.
  Without an id it yields **every** Story - so the URL validator requires the id.
  `/stories/highlights/<id>` also matches this extractor; Highlights are a non-goal and are rejected.
* Stories need a logged-in session (`sessionid` cookie). Whether `user.is_private` and
  `audience` are exposed reliably enough to prove "public" is **unverified** (T01.5); until it is,
  the adapter fails closed on unknown visibility.

### X / Twitter (T01.6)

* `twitter:tweet` accepts `x.com`/`twitter.com`, `/<user>/status/<id>`, `/i/web/status/<id>` and
  trailing `/photo/N` / `/video/N`.
* Defaults already exclude quoted tweets (`quoted=false`), retweets, cards and text-only tweets;
  the adapter sets them explicitly anyway, and also disables Articles.
* Video items are the highest-bitrate progressive variant; each file carries `type`
  (`photo` / `video` / `animated_gif`), `num`, `width`, `height`.

## 4. Licences and dependency policy (T01.7)

* **gallery-dl is GPL-2.0-only.** It is invoked **only as a subprocess** and never imported, so the
  project's own code is not a derivative work. If a bundled release containing gallery-dl is ever distributed, the GPL
  obligations for that component (source offer) apply to that distribution. Private self-hosted use has none.
* yt-dlp is the Unlicense (public domain-style). aiogram, pydantic, pydantic-settings: MIT.
  aiohttp: Apache-2.0 AND MIT.
* Both extractors are pinned **exactly** in `pyproject.toml`, locked in `uv.lock` and exported with
  hashes to `requirements.lock`. No forks, no unknown downloader endpoints.
* Upgrading an extractor is a deliberate act: run `pytest`, then the live probe, then update the pin.

## 5. Known extractor-level risks (carry into implementation)

1. TikTok photo mode depends on gallery-dl scraping the web page's rehydration data and solving a JS
   challenge; it can break without notice. Typed `EXTRACTOR_CHANGED` + a clear message, no fallback.
2. Instagram needs session cookies for Stories and increasingly for posts; `request_interval`
   defaults to 6-12 s per request, so expect multi-second latency per post.
3. X may require a session for some tweets; `AUTH_REQUIRED` must be reported, never worked around.
4. None of these three platforms promises API stability; the live probe is the regression test.

the platforms. The live probe / `pytest -m live` should confirm or refute every one; a refuted assumption
must be recorded here and the adapter changed (or the content type declared blocked).
